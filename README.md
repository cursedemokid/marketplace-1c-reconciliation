# Сверка Wildberries, куба и 1С

Стартовый проект по краткому ТЗ v2 от 24 сентября 2026 года. Короткий документ является актуальным ТЗ — это подтвердил заказчик. Исходники обоих ТЗ сохранены в `docs/source`; v1 оставлен как справочный материал.

Подготовлены три режима CLI, нормализованная модель источников, сравнение, выгрузка XLSX, журнал запусков и настройки VS Code. Демонстрация работает на искусственных данных. Реальные подключения WB, PostgreSQL и 1С, интерфейс с кнопкой запуска и распознавание УПД/счетов-фактур ещё не реализованы. Финансовые формулы и соответствия источников не утверждены. Проект не выполняет сетевых запросов и не изменяет источники.

## Открытие в VS Code

Откройте файл `wb-1c-reconciliation.code-workspace` через **File → Open Workspace from File** либо выполните из каталога проекта:

```sh
code wb-1c-reconciliation.code-workspace
```

Нужен Python 3.11 или новее. Сторонние библиотеки для запуска и тестов не нужны. В VS Code выберите установленный Python через **Python: Select Interpreter**. Рекомендованные расширения Python и Python Debugger позволяют запускать демонстрации через F5 и работать с тестами. Проект также запускается в обычном терминале без расширений.

## Быстрый запуск

Команды выполняются из корня проекта. На Linux обычно используется `python3`; на Windows — `py` или `python`.

```sh
python3 -m wb_reconcile run --mode daily --start 2026-08-01 --end 2026-08-01 --demo
python3 -m wb_reconcile run --mode weekly --start 2026-08-03 --end 2026-08-09 --demo
python3 -m wb_reconcile run --mode monthly --start 2026-08-01 --end 2026-08-31 --demo
```

Каждая команда создаёт новую Excel-книгу и JSON-журнал в `reports/`. Уникальный идентификатор сохраняет историю повторных запусков. Для одинакового периода демонстрационные исходные значения и разницы повторяются. В демонстрации намеренно присутствует расхождение первой пары: код завершения **2 ожидаем**.

Коды завершения: `0` — все сравнения совпали, `1` — ошибка входных данных/сохранения, `2` — найдено расхождение, `3` — неполные данные или неподтверждённые правила. Неподключённые адаптеры без `--demo` формируют Excel со статусом неполноты и кодом `3`; демонстрационные данные автоматически не подставляются. Ошибки аргументов argparse, например неизвестный режим, также дают код `2`, но выводятся в stderr до создания отчёта.

Допустимые периоды: `daily` — один день или семь дней с отдельным результатом по каждому дню; `weekly` — ровно семь дней; `monthly` — полный календарный месяц. Начало недели и часовой пояс ещё не утверждены, даты автоматически не сдвигаются.

## Что находится в проекте

| Путь | Назначение |
|---|---|
| `wb_reconcile/domain.py` | Периоды, разрезы, точные десятичные значения, сравнение и статусы |
| `wb_reconcile/catalog.py` | Рабочие названия показателей из ТЗ |
| `wb_reconcile/adapters.py` | Протокол адаптера, искусственные источники и закрытые неподключённые адаптеры |
| `wb_reconcile/engine.py` | Изоляция источников по режимам и общий статус запуска |
| `wb_reconcile/report.py` | Формирование листов результата и ссылок на исходные строки |
| `wb_reconcile/excel.py` | Локальная запись XLSX без сторонних библиотек |
| `wb_reconcile/cli.py` | Командный интерфейс и безопасный журнал |
| `config/rules.draft.json` | Документальный реестр неподтверждённых соответствий, пока не исполняемая конфигурация |
| `docs/requirements.md` | Требования актуального ТЗ |
| `docs/integrations.md` | Контракты источников и решения до разработки интеграций |
| `examples/` | Проверенные демонстрационные Excel и журналы трёх режимов |
| `tests/` | Автоматические проверки поведения |

В `daily` используются только `cube` и `wb_reports`; детализация WB отсутствует. В `weekly` используются только `one_c` и `cube`. В `monthly` формируются независимые пары `wb_documents − cube` и `wb_documents − one_c`. Направление разницы предварительное и разрешено только для демонстрации.

## Excel и ограничения стартовой реализации

Листы: **Сводка**, **Сравнения**, **Источники**, **Покрытие**, **Документы**. Числа сохраняются текстом, чтобы Excel не потерял точность десятичных значений и больших идентификаторов. Данные, похожие на формулы, записываются как текст. Пустое значение остаётся пустым; нулевой итог не подставляется. Документные строки демонстрации искусственные, извлечение оригиналов отсутствует.

Общий итог не скрывает отдельных расхождений. Разные организация, кабинет, сегмент, валюта, единица, период и показатель образуют разные ключи. Повтор одного идентификатора строки в одном ключе считается дублем, его сумма не используется в сравнении. Пересчёт с теми же исходными строками повторяет значения и создаёт новый файл; промышленное хранение версий снимков и корректировок ещё предстоит разработать.

Пока нет нормализованных исходных контрактов, каркас использует общий статус «нет данных» и отражает конкретные стороны в столбцах источников. Состояния позднего документа, неопределённого периода и ошибок распознавания описаны в требованиях, но их обнаружение и парсеры ещё не реализованы. XLSX формируется в памяти и рассчитан на небольшие пилотные результаты.

## Проверка

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют периоды, Decimal, пропуски, дубли, разрезы, неподтверждённые правила, источники режимов, две месячные пары, структуру XLSX, защиту от формул и сохранение истории. В VS Code доступны Test Explorer и задача **Проверить проект**.

## Перед подключением данных

Нужны read-only схема и поля PostgreSQL-куба, согласованный интерфейс 1С, контрольный день для поля WB «Итого к оплате», утверждение знаков, НДС и округления. Необходимы локальные образцы документов WB для проверки форматов и периода в названии. Полный перечень — в `docs/integrations.md`.

Для разработки реального адаптера реализуйте `fetch(Period) -> Snapshot`, возвращайте Decimal из исходных строк, сохраняйте идентификаторы и выставляйте `complete=False` при неполноте. Затем добавьте маршрутизацию и интеграционные тесты на обезличенных ответах; отдельный механизм утверждённых правил обязателен до боевых сравнений. Сейчас `approved=demo` намеренно блокирует все реальные расчёты.

Секреты храните вне репозитория и выгрузок. `reports/`, `data/`, `.env` и виртуальное окружение исключены из Git. Оригиналы документов и извлечённые финансовые данные обрабатываются локально и не должны передаваться внешним ИИ-сервисам. У новых отчётов и журналов на POSIX права доступа `0600`; для промышленного использования потребуются согласованные контроль доступа и хранение.
