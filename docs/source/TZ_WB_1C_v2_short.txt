Краткое техническое задание на сверку WB, куба и 1С
Версия 1.0 · 24 сентября 2026 года
Система запускает один из трёх независимых видов сверки и формирует Excel с результатами и статусом полноты данных. Все источники используются только для чтения. Подробные требования и контекст сохранены в ТЗ v2 (TZ_WB_1C_v2.md); этот документ — краткая рабочая редакция.

2. Требования по режимам
2.1 Ежедневная сверка
Для выбранного дня система сравнивает расчётную меру куба «Оплата от WB (Заливка)» с показателем личного кабинета WB «Итого к оплате». При выборе недели формируются семь отдельных дневных результатов. Используется API «Список отчётов реализации» (https://dev.wildberries.ru/docs/openapi/documents-and-accounting#tag/financialReports/operation/postV1SalesReportsList); загружаются все страницы списка. Детализация операций WB не запрашивается и не загружается.
Точное поле API, соответствующее «Итого к оплате», и правило суммирования нескольких или исправленных отчётов подтверждаются на контрольном периоде. До подтверждения нельзя автоматически подставлять forPaySum, bankPaymentSum или другое поле.

2.3 Ежемесячная сверка документов WB
Документы типов «УПД» и «Счёт-фактура» из API «Документы» (https://dev.wildberries.ru/docs/openapi/documents-and-accounting#tag/documents) сверяются за выбранный месяц с кубом и отдельно с 1С. Для обеих сторон показываются самостоятельные значения, разницы и статусы. Рабочее допущение: сравниваются месячные итоги по услугам, а Excel содержит реестр документов и строк. Нужен ли отдельный результат по каждому УПД — открытый вопрос.
Месяц определяется по периоду в названии документа; при конфликте название имеет приоритет. Если периода в названии нет или он неразборчив, ставится статус «период не определён» без подстановки даты из содержимого или списка. Из документа извлекаются номер, дата, наименования строк, сумма без НДС и с НДС, ставка и сумма НДС, итог документа. Точные показатели 1С для сравнения документов ещё предстоит согласовать. Многоточие в наименовании услуги означает изменяющиеся номера или даты.

Возмещение эквайринга
Документы по эквайрингу могут поступать с задержкой. За месяц суммируется общая сумма всех документов именно по услуге эквайринга, после чего итог отдельно сопоставляется с кубом и 1С; позднее поступление должно быть видно в результате и позволять пересчёт месяца. Форматы файлов и возможность автоматического распознавания через API пока не проверены. Распознавание и обработка разрешены только локально; внешним ИИ-сервисам нельзя передавать оригиналы документов, изображения страниц или извлечённые финансовые данные.
3. Результат и критерии приёмки
Для каждого запуска формируется Excel с выбранным режимом и периодом, исходными значениями, результатами сравнений, реестром источников и статусами. Неполные или отсутствующие данные не заменяются нулём и не считаются совпадением. Ошибки загрузки, нераспознанные строки, дубликаты, поздние документы и неустановленный период отмечаются отдельно.
Сверка принимается, если:
Пользователь выбирает режим и допустимый для него период.
Каждый режим использует только указанные источники; дневной режим не загружает детализацию WB, недельный не вызывает WB API.
Выгрузка содержит обе стороны сравнения и разницу; месячный режим показывает отдельные результаты для куба и 1С.
Неполные данные, ошибки и неразрешённые соответствия имеют явный статус.
Проверка на согласованных контрольных данных совпадает с утверждённым результатом.
4. Открытые вопросы и пилот
До настройки расчётов нужно: согласовать доступ только для чтения, схему и поля PostgreSQL; подтвердить поле API для «Итого к оплате» на контрольном дне; с Димой Соколовым уточнить физические поля куба, а с владельцем 1С — недельные пары и месячные показатели; утвердить знаки разниц, НДС, округление, начало недели и часовой пояс; получить токен категории «Документы» и проверить локально фактические форматы, комплектность и читаемость УПД/счетов-фактур. До этого API-поля, автоматическое распознавание и финансовые формулы считаются неподтверждёнными.
