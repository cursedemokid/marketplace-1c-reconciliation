# Требования к проекту сверки WB, куба и 1С

## Назначение и границы стартового проекта

Проект предназначен для запуска сверок Wildberries (WB), PostgreSQL-куба и 1С по выбранному периоду и подготовки Excel-отчёта. Это стартовый проект с CLI и демонстрационными синтетическими данными, а не готовая промышленная интеграция. Для запуска нужен Python 3.11 или новее; используются только модули стандартной библиотеки, установка сторонних пакетов не требуется.

Краткое ТЗ `docs/source/TZ_WB_1C_v2_short.txt` считается актуальной рабочей редакцией требований и отражает второе, последнее ТЗ. Более ранняя редакция v1 не задаёт требования проекта. Указанные в ТЗ неподтверждённые поля, формулы и сопоставления остаются открытыми вопросами и не должны подменяться догадками.

Запуск из корня проекта:

```text
python -m wb_reconcile run --mode daily|weekly|monthly --start YYYY-MM-DD --end YYYY-MM-DD [--demo] [--output-dir reports]
```

В демонстрационном режиме `--demo` используются только синтетические фикстуры; они должны быть явно обозначены в отчёте как демонстрационные и не представляться данными WB, куба или 1С. Без демо-режима незаполненные или неподтверждённые адаптеры источников должны завершаться понятной ошибкой конфигурации. Нельзя незаметно заменять отсутствующие боевые данные фикстурами.

## Режимы и периоды

Все даты задаются в формате ISO `YYYY-MM-DD`, включительно. Некорректная дата, диапазон с началом позже окончания или период, не соответствующий режиму, отклоняется до обращения к источникам.

| Режим | Допустимый период | Источники | Содержание |
|---|---|---|---|
| `daily` | Один календарный день или ровно 7 последовательных календарных дней. Для диапазона в 7 дней принудительное совпадение с календарной неделей пока не установлено. | PostgreSQL-куб и список отчётов WB | По каждому дню сравнить меру куба «Оплата от WB (Заливка)» с показателем WB «Итого к оплате». Семидневный диапазон даёт семь отдельных дневных результатов. |
| `weekly` | Ровно 7 последовательных календарных дней. День начала недели и часовой пояс требуют согласования; CLI не должен молча сдвигать даты. | PostgreSQL-куб и 1С | Сравнить семь рабочих пар показателей, перечисленных ниже. WB API в этом режиме не вызывается. |
| `monthly` | Полный календарный месяц: начало — первый день месяца, окончание — последний день того же месяца. | Документы WB, куб и 1С | Суммы документов за месяц показать отдельно в сравнении с кубом и с 1С; сформировать реестр документов и строк. |

### Рабочие пары еженедельной сверки

Названия являются рабочими отображаемыми названиями; физические поля, единицы измерения, разрезы и агрегацию требуется подтвердить у владельцев данных. Это особенно важно для рабочего названия 1С «Ед. хранения», смысл и единицы которого не установлены.

| Показатель 1С | Рабочее название показателя куба |
|---|---|
| Ед. хранения | WB реал,ШТ |
| С НДС | WB реализ,Итого |
| Сумма заливки | Итого продажи руб_ |
| Ретро-бонус | Комиссия (полка) |
| Логистический бонус | Логистика Итого |
| Санкции | Штрафы |
| Эквайринг | Возмещение эквайринга |

Эти семь отображаемых пар проверены по ячейкам таблицы DOCX. Физические поля куба и 1С, единицы измерения и смысл рабочего названия 1С «Ед. хранения» всё ещё требуют подтверждения; до этого пары не считаются готовыми к боевому расчёту.

### Ежедневная сверка

Для WB используется только API «Список отчётов реализации» из категории финансовых отчётов. Необходимо получать все страницы списка. Детализация операций WB не запрашивается. Поле API для показателя «Итого к оплате» и правила выбора/суммирования нескольких, исправленных или повторных отчётов подтверждаются на контрольном периоде. До этого нельзя автоматически подставлять `forPaySum`, `bankPaymentSum` или другое поле.

### Ежемесячная сверка документов

Обрабатываются документы WB типов «УПД» и «Счёт-фактура». По рабочему допущению сравниваются месячные итоги по услугам; Excel включает реестр документов и строк. Нужен ли отдельный результат для каждого УПД, остаётся открытым вопросом.

Месяц документа определяется только по периоду в названии файла/документа. Если период отсутствует или неразборчив, присваивается статус «период не определён». Даты внутри документа, дата публикации и даты из списка не используются как резервная подстановка. Из распознанного документа требуется извлечь номер, дату, названия строк, суммы без НДС и с НДС, ставку и сумму НДС, итог.

Рабочие соответствия услуг документов показателям куба:

| Тип и строка WB | Показатель/строка куба |
|---|---|
| УПД: «Услуга возмещение за выдачу и возврат товаров на ПВЗ…» | Возмещение за выдачу и возврат товаров на ПВЗ |
| УПД: «Услуга возмещение расходов по перевозке…» | Возмещение издержек |
| УПД: «Штраф за нарушение правил площадки» | Штрафы |
| УПД: «Вознаграждение агента по отчёту…» | Вознаграждение WB без НДС + НДС с вознаграждения WB |
| УПД: «Оказание услуг „WB Продвижение“» | Удержания, где Bonus Type Name содержит «Оказание услуг „WB Продвижение“» |
| УПД: «Оказание услуг „WB Медиа“» | Удержания, где Bonus Type Name содержит «Оказание услуг „WB Медиа“» |
| Счёт-фактура: услуги проведения расчётов по операциям с использованием банковских карт и систем платёжных сервисов | Возмещение эквайринга |

Многоточие в названии строки означает изменяющиеся номера или даты. Документы по эквайрингу могут поступать с задержкой: месячная сумма должна учитывать найденные документы именно по услуге эквайринга, показывать позднее поступление и допускать повторный расчёт месяца.

## Правила расчёта и полноты

- Каждая сторона сравнения и её исходная сумма должны быть доступны в отчёте отдельно.
- Рабочее направление разности: левая сторона минус правая. Для ежемесячного режима показываются две самостоятельные разности: документы минус куб и документы минус 1С. Направление является предварительным и не утверждено для боевого применения; оно должно быть параметром/явно указанной конвенцией, пока владелец процесса его не утвердит.
- НДС, точность хранения, округление, допуски совпадения и финансовые формулы нельзя додумывать. До согласования сравнение, требующее таких правил, отмечается как неподтверждённое.
- Отсутствующие или неполные данные не заменяются нулём и не считаются совпадением. Различать как минимум: совпало, есть расхождение, неполные данные, источник недоступен/ошибка, сопоставление не подтверждено, период не определён, дубль/повторный источник.
- Ошибки загрузки, нераспознанные строки, дубликаты, поздние документы и неустановленный период должны быть видны отдельно от денежных разниц.
- Источники только для чтения: сверка не изменяет записи в кубе или 1С и не выполняет действий, меняющих данные WB.

## Выходной файл

Каждый успешный запуск формирует Excel-книгу в каталоге, указанном `--output-dir` (по умолчанию `reports`). Она содержит выбранный режим и даты, исходные значения, разности, статусы полноты, ошибки/замечания и реестр использованных источников. Предусмотрены листы:

| Лист | Содержание |
|---|---|
| `Сводка` | Режим, период, время формирования, общий статус и краткие итоги. |
| `Сравнения` | Сравниваемые стороны, показатель, значения и разность; для месяца — отдельные сравнения документов с кубом и 1С. |
| `Источники` | Использованные источники, параметры периода, время/состояние загрузки и ошибки. |
| `Покрытие` | Полнота по дням, показателям и источникам, явные пропуски. |
| `Документы` | В месячном режиме — реестр документов и извлечённых строк, включая периоды и поля распознавания. |

Формат листов допускает русские названия. Если конкретная реализация временно не может создать корректный Excel, она должна явно завершить запуск с ошибкой, а не выдавать файл иного формата с расширением `.xlsx`.

## Приёмка и готовность к боевому подключению

Критерии приёмки предметной сверки: пользователь выбирает один из трёх режимов и допустимый период; каждый режим вызывает только назначенные источники; дневной режим не загружает детализацию WB; недельный не вызывает WB API; месячный выводит отдельные сравнения с кубом и 1С; результат содержит обе стороны и разность; ошибки и неполнота явно отражены; контрольный набор совпадает с утверждённым результатом.

Стартовый проект может быть запущен с синтетическим демо-режимом. Это не подтверждает готовность боевых расчётов. Боевой режим допустим после согласования доступа только для чтения, схемы и полей PostgreSQL, поля WB API и правил обработки отчётов, физических соответствий куба и 1С, знака разности, НДС и округления, начала недели и часового пояса, а также проверки реальных форматов и комплектности документов.
